# Token Usage Lab 使用说明书

版本：0.1.0，macOS 同事内部试用版。

这是一个独立的桌面应用，用于汇总当前 Mac 用户的 AI 工具本地日志中已报告的 Token 用量。它不提供模型调用，不切换模型配置，也不是需要安装到 Agent 里的插件。Agent 可以协助安装，但应用运行不依赖 Agent。

## 一、拿到包后怎么开始

1. 在 Mac 的“关于本机”中查看芯片。Apple M 系列使用名称含 `apple-silicon` 的包；Intel 使用名称含 `intel` 的包。不要把 Windows EXE 用在 Mac 上。
2. 解压整个 ZIP，确认下面列出的七个文件都在同一个文件夹中。
3. 阅读本文，确认来源可信，并核对文件完整性。
4. 打开 `.dmg`，将 `Token Usage Lab.app` 拖入 `Applications`。没有系统应用目录写入权限时，可放入当前用户的 `~/Applications`，不要为安装申请不必要的管理员权限。
5. 从应用目录启动 Token Usage Lab。安装后可弹出 DMG，无需一直保持磁盘映像挂载。

无需安装 Node.js、Rust、Docker 或其他开发工具，无需编译源码、注册账号、填写 API Key 或打开开发网页。

构建目标为 macOS 12 及以上，Apple Silicon 和 Intel 都提供原生程序；目前仅在 macOS 15.7.9 的原生 CI 环境验证了安装包、启动和重启。旧系统及同事真实工具日志仍需试用确认。

## 二、直接交给 Agent 安装

可以把整个 ZIP 交给能操作这台 Mac 的本地文件和终端的 Agent。只有聊天能力、无法访问本机的 Agent 不能直接完成安装。可以发送下面这段话：

> 请安装并启动附件中的 Token Usage Lab。先解压并阅读 README.md 和 START-HERE.txt，确认本机芯片与安装包匹配，并核对 SHA256SUMS.txt。只操作本次分享包和应用安装目录，将应用放到当前用户的 ~/Applications；如果已有同名应用，先询问我，不要覆盖。无需安装开发环境，不要修改其他 AI 工具配置、启用代理或发起模型调用。安装后启动应用，查看采集状态，报告是否正常显示，不要把未覆盖当作零消耗。若 macOS 或公司安全策略阻止运行，请停止并告诉我需要确认的步骤，不得关闭防护、删除隔离属性或使用绕过脚本。不要上传我的聊天日志、数据库、密钥或配置文件。

Agent 可以完成解压、校验、复制和尝试启动；系统要求的用户确认仍需本人处理。安装后可以关闭 Agent，单独使用本应用。

## 三、首次打开的安全提示

本版本只有 ad-hoc 签名，没有 Apple Developer ID 签名或 Apple 公证。下载或传输后，macOS 可能提示无法验证开发者并阻止打开；这不等于已经通过 Apple 的安全审核，也不能保证双击即可运行。

- 先核对发件人和文件来源。校验和只能检查完整性，不能单独证明发布者可信。
- 如符合公司政策，可按 macOS 提供的单个应用授权流程操作；受公司管理的电脑先联系 IT。
- 如果系统明确报告恶意软件、文件损坏、校验失败，或公司策略禁止运行，请停止使用并反馈，不要强行继续。
- 不要关闭 Gatekeeper，不删除下载隔离属性，不关闭杀毒软件，不运行“解锁”脚本。

需要无需额外授权的正式分发版本时，还需完成 Developer ID 签名、Apple 公证及下载后的 Gatekeeper 验证。

## 四、日常怎么查看用量

1. 使用安装了 AI 工具、且保存过本地会话日志的同一个系统账号启动本应用。
2. 等待启动采集。首次扫描历史日志较多时可能较慢；近期已经扫描过的来源会跳过重复的启动扫描。
3. 在“来源”中选择工具，在“模型”中选择模型，并选择需要的日期范围。
4. 查看已采集 Token、模型调用、新增输入、输出、缓存命中、缓存写入和用量趋势。
5. 使用“调用明细”“模型统计”“来源统计”和“采集状态”查看对应记录、汇总及采集问题。
6. 需要重新扫描时点击刷新按钮。应用运行期间默认每 60 秒自动采集；后台刷新保留已有显示，不必反复关闭重开。

新调用只有在原工具写出可识别的用量日志后才能被发现，不保证实时、完整覆盖。应用完全退出后不会继续采集，不自动开机启动，也不依靠云端后台采集。Mac 上关闭窗口不一定等于退出进程；需要停止运行时，从应用菜单选择退出。

## 五、目前统计哪些工具

当前有九个本地采集器：

| 工具        | 默认读取范围                                                              |
| ----------- | ------------------------------------------------------------------------- |
| WorkBuddy   | `~/.workbuddy/projects/**/*.jsonl`                                        |
| Codex       | `~/.codex/sessions/**/*.jsonl` 和 `~/.codex/archived_sessions/**/*.jsonl` |
| Claude Code | `~/.claude/projects/**/*.jsonl`，包括可识别的子代理记录                   |
| OpenClaw    | `~/.openclaw/agents/*/sessions/*.jsonl`                                   |
| Gemini CLI  | `~/.gemini/tmp/*/chats/session-*.json(l)`                                 |
| Pi          | `~/.pi/agent/sessions/**/*.jsonl`                                         |
| OpenCode    | `~/.local/share/opencode/opencode.db`，新版 SQLite 存储                   |
| Kilo Code   | `~/.local/share/kilo/kilo.db`，新版 SQLite 存储                           |
| Qwen Code   | `~/.qwen/tmp/*/chats/*.jsonl`                                             |

`~` 表示当前系统用户的主目录。当前没有自定义采集目录的界面入口；其他系统账号、远程机器、网页端以及不落本地用量日志的调用不在采集范围内。不要为了让应用找到日志，随意移动原工具的数据或修改原工具配置。

不承诺覆盖市面上全部工具。Cursor、Windsurf、Trae、GitHub Copilot、Cline、Roo Code、CodeBuddy、Continue、Aider 等尚未宣称接入；Kilo 旧版 VS Code 任务日志、OpenCode 旧版 JSON 和 Qwen 托管会话存储也不在当前支持范围内。

九个采集器在 Mac 上的真实日志兼容性仍待实机验证。此前 Windows 的实测结果和 CI 合成样本不代表同事的 Mac 工具版本已通过验收。

## 六、数字和状态应该怎么理解

- **已采集 Token**：来自已识别日志，不是设备上全部 AI 消耗或服务商账单。
- **缓存**：按适配器的字段口径拆分，避免把输入中已包含的缓存重复计入总量。不要手动把原工具显示的输入再与缓存相加进行比较。
- **未覆盖 / 未发现目录 / 暂无记录**：当前没有可供可靠统计的数据，不代表消耗为零。先查看“采集状态”。
- **部分覆盖 / 格式不支持 / 读取失败**：存在不能可靠计量或不能读取的数据；已显示数字也不能当作完整总量。
- **参考费用未知 / 实际账单未接入**：没有足够价格依据或没有对接账单，不代表免费。不将积分、文本长度或请求数换算成 Token。
- **后台任务 / 未归因**：不把当前电脑用户直接认定为每一个后台调用的实际发起人。

正常重复扫描和重启不应累计重复用量。同一调用的有效修订可能更新原有数字，因此变动不一定等于新增调用；发现异常时不要直接删除账本来掩盖问题。

## 七、没有数据或打不开怎么办

| 现象                 | 建议检查                                                                                               |
| -------------------- | ------------------------------------------------------------------------------------------------------ |
| 打不开应用           | 核对芯片、系统版本和校验结果，查看系统提示；遇到安全策略拦截按第三节处理。                             |
| 全部显示未覆盖       | 确认是实际使用 AI 工具的系统账号，确认相关默认目录有已有日志，再手动刷新。无需主动发起付费调用来测试。 |
| 只有某个工具没有数据 | 查看该来源的采集状态，确认工具版本、存储格式及目录是否在第五节范围内。                                 |
| 数字与工具页面不同   | 对照相同日期、模型、来源以及缓存口径；云端账单、积分和本地日志不是同一种数据。                         |
| 新记录迟迟不出现     | 确认原工具已写入日志，等待自动扫描或手动刷新一次。不要修改原始日志。                                   |
| 扫描失败或部分覆盖   | 保留状态提示并反馈，不要因此删除日志、修改权限或授予整个磁盘访问权限。                                 |

反馈时提供应用版本、macOS 版本、芯片类型、工具名称及版本、操作步骤、采集状态，以及遮挡个人信息后的截图。不要发送完整聊天日志、数据库、API Key、访问令牌或其他工具配置文件。

## 八、隐私、更新与卸载

统计只保存在当前用户本机，不上传、不云同步，也不会自动把同事的用量传回发件人。程序读取日志提取计量字段，不保存聊天正文、工具参数、原始日志或密钥，不修改原工具配置，也不读取或迁移 CC Switch 的数据库。

独立统计账本位于：

```text
~/Library/Application Support/TokenUsageLab/token-usage-lab.sqlite3
```

更新前退出应用，先确认要替换已有版本，不要同时运行多个副本。删除 `.app` 可移除程序，但不会自动删除上述本地账本，也不会删除其他 AI 工具日志。只有在明确不需要保留统计数据时，再由用户决定是否处理本应用的数据目录。

## 九、包内文件与校验

| 文件                                       | 用途                                     |
| ------------------------------------------ | ---------------------------------------- |
| `README.md`                                | 本说明书，供同事及其 Agent 阅读。        |
| `TokenUsageLab-0.1.0-macos-*-internal.dmg` | 与芯片匹配的已编译应用。                 |
| `START-HERE.txt`                           | 随原安装包提供的简明试用说明。           |
| `BUILD-INFO.json`                          | 原应用构建的版本、提交、架构及验收范围。 |
| `SHA256SUMS.txt`                           | 包内六个其他文件的 SHA-256。             |
| `LICENSE`                                  | 上游 MIT 许可证。                        |
| `THIRD-PARTY-NOTICES.txt`                  | 第三方依赖许可证声明。                   |

在解压后的文件夹打开终端，可以使用系统自带命令检查全部列出的文件：

```sh
shasum -a 256 -c SHA256SUMS.txt
```

每个条目都应显示 `OK`。如果发件人同时提供 ZIP 的 `.sha256` 文件，可在解压前核对 ZIP。出现任何失败就停止安装并重新联系发件人。

本次新增的是外层分享包中的 Markdown 说明书，DMG 和应用二进制沿用已验收版本，未因补充文档而重新构建或获得 Apple 公证。原生启动验收不等于全部工具日志、所有界面交互及所有 macOS 版本均已验收。
